### Динамический курс USD/RUB (вместо хардкоднутого 95)

**Проблема:** В коде везде `USD_TO_RUB = 95.0` (см. `backend/app/config.py`). Реальный курс ЦБ часто другой.

**Сейчас (апрель 2026):**
- Реальный курс: ~77 ₽/$
- Наш курс: 95 ₽/$
- Разница 23% — **в нашу пользу** (скрытая маржа на конвертации)

**Когда выстрелит:** если ₽ ослабнет к 95-100+, начнём терять деньги на каждом списании API.

**Вариант решения:**
- Сервис, который раз в день тянет курс ЦБ
- Применяем буфер +10% (для защиты от движений)
- Показываем юзеру "наш курс: $X = Y₽"
- Миграция старых балансов (если меняем формулу)

**Файлы для изменения:**
- `backend/app/config.py:9` — `USD_TO_RUB = 95.0`
- `backend/app/routers/payment_ext.py` — пополнения и подписки
- `backend/app/routers/user.py:801` — `/api/subscribe` endpoint
- Все места с `USD_TO_RUB` (~10 файлов)

**Приоритет:** низкий пока курс в нашу пользу. Поднимать когда ₽ поползёт к 90+.

## 🟢 Инфраструктура / прозрачность

### Сверка реальных трат провайдеров с нашими расчётами
Сейчас нет автоматической сверки между:
- Что мы записали в БД (`provider_cost_usd`)
- Что реально списал провайдер (Novita dashboard, fal.ai dashboard)

**Идея:** ежедневный job который дёргает API провайдера за usage и сравнивает с нашими записями. Алерт если расхождение > 10%.

### Cap на output tokens
Сейчас нет ограничения на длину ответа моделей. Один power-user может запросить `max_tokens=64000` и сжечь бюджет.
Нужно:
- Cap для `fast` тира: max 1500 output
- Cap для `premium`: max 2000 output
- Cap для `opus`: max 2000 output
- Cap input context для opus: 8k

### Image output token cap
nano-banana-pro и gpt-5-image при больших картинках (5-8k image tokens) могут стоить $0.06 вместо $0.012.
Зафиксировать output на 1024×1024.

### Reset 1-го числа vs 30 дней
Сейчас видео-поинты сбрасываются 1-го числа UTC. Подписка же продлевается через 30 дней от даты оплаты.
Это означает: юзер платит 25-го числа, через 6 дней (1 число) поинты сбрасываются — он "теряет" 24 дня.
Нужно либо синхронизировать reset с датой подписки, либо предупреждать юзеров об этом.
